Реалізуйте спрощений сервіс конференцій із “кімнатами” (rooms), списком учасників, чатом у реальному часі та відеозв’язком WebRTC. Дані повинні зберігатись у json-файл MongoDB. Загальна модель:
rooms — кімнати конференцій
participants — учасники кімнати (стан “активний/вийшов”)
messages — чат-повідомлення
rtc_sessions — (опційно) діалоги/сесії сигналінгу WebRTC
Учасник не видаляється фізично: ставте left_at, щоб бачити історію. Повідомлення завжди прив’язані до room_id і автора participant_id. Для реального часу WS тримає в пам’яті список підключень; БД – “джерело істини” для історії/відновлення.
Базові REST-методи та ендпоінти:
POST /rooms – створити кімнату
GET /rooms – отримати список кімнат
GET /rooms/:roomId – інформація про кімнату
POST /rooms/:roomId/close – закрити кімнату
DELETE /rooms/:roomId – видалити кімнату
POST /rooms/:roomId/join – приєднати учасника
POST /rooms/:roomId/leave – покинути кімнату
GET /rooms/:roomId/participants – список активних учасників
GET /rooms/:roomId/messages?limit=50 – отримати історію чату
POST /rooms/:roomId/messages – надіслати повідомлення через HTTP
Вимоги до API
Формат обміну — JSON (Content-Type: application/json)
Валідація: порожні name або text → 400 Bad Request
Узгоджені статус-коди: 200/201/204/400/404/409/500
Обов’язкова помилка у форматі JSON, наприклад: { "error": "ValidationError", "message": "name is required" }
Після успішного приєднання користувача (через REST) клієнт відкриває WebSocket-з’єднання та підписується на події кімнати:
join (клієнт → сервер): { roomId, name, participantId } (participantId можна з join HTTP)
participants_list (сервер → клієнт): { participants:[...] }
user_joined, user_left
chat_message: { from, text, ts }
Якщо WS розірваний, клієнт намагається перепідключитись (простий backoff: 1с, 2с, 5с). Повідомлення можуть прийти після реконекту повторно.
При події leave закривайте WS і прибирайте слухачі.
Серверні може логувати type, roomId, кількість клієнтів у кімнаті. Опційно засобами Wireshark можна моніторити безпекові питання, зокрема, WebSocket поверх TLS буде шифрований.
